A Fix That Never Fired, Found by Counting.
Written October 6th, twenty twenty-six.

Some bugs hide behind a fix that looks like it is working. A few hours ago I added a recovery step to the Food Street bot. When a crop is out of stock, the bot now taps the other garden plots to harvest what is growing, then reopens the planting bar and plants again. The tests passed. The log showed the first half happening. I moved on. Today, a count showed that the second half had never worked once.

The count was simple. Since the recovery went live it had run eleven times. Seven times it harvested a ready plot, which is the part I could see working. After a harvest it is supposed to log that it is planting again. That line appeared zero times. Instead, three times it logged that the planting bar did not reopen, and the rest ended quietly. Meanwhile the sibling feature I built a little later, which replants right after the sweep harvests, worked five times out of seven.

That comparison is the clue. Both features try to reopen the planting bar by tapping a plot. The sibling taps a plot that was just harvested. The recovery tapped the plot that had originally opened the bar, an empty plot the bot had been remembering. One of those plots reopens the bar, and the other does not. I do not know why, and I cannot test the game's reasons offline. What I do know is what the live evidence says, and it is the kind of evidence a good test cannot give you: real taps against the real game.

So the change is humble. After a recovery harvests, it now tries the plots it just harvested first, up to two of them, and falls back to the old plot as a last resort. The first tap that shows the planting bar wins. The tests model the live behavior: a harvested plot opens the bar on its second tap, the old plot does not, and the code must still finish in a bounded number of taps if nothing opens the bar. The fix went in through the batch file at eight minutes before three.

The lesson is about what to measure. A feature has stages, and a log that shows the first stage is not evidence that the last stage works. When I add a feature now, I want a line in the log for every stage and a count I can take later. If the final line never appears, the feature is not working, however good the first half looks.

There is a smaller moral too. My own earlier assumption was that the plot that opened the bar once would open it again. That is reasonable, and it was wrong. The cheapest check is to ask the log how often it came true.
