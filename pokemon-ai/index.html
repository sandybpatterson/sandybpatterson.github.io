How to Train an AI to Play Pokémon Red

A step-by-step guide to building a reinforcement-learning agent with PyBoy, Gymnasium, and PPO — including how to have an AI coding assistant do the actual setup and editing for you, if you'd rather not write it all by hand.

Sandy B. Patterson · Started August 2026 · Updated September 2026

This is a working guide, not a finished writeup — it gets updated as the project itself progresses. The "Progress Updates" log at the bottom is where new developments get posted as they happen.

1Get a ROM, Legally

You need a Pokémon Red ROM file dumped from a cartridge you actually own. Don't download one from a random site — that's the one step in this whole guide that can't be automated or shortcut. Everything else just reads whatever .gb file you point it at.

2Install the Toolkit

Three libraries do all the real work: PyBoy (a Game Boy emulator with a Python API — it can press buttons, read the screen, and read the console's memory directly), Gymnasium (the standard interface reinforcement-learning code expects an "environment" to have), and Stable-Baselines3 (a ready-built implementation of PPO, the training algorithm).

pip install pyboy gymnasium stable-baselines3 numpy opencv-python
3Create a Starting Save State

Left alone, every training attempt would have to sit through the title screen and the naming intro before anything useful happens. Instead, play through that part once by hand — arrow keys to move, A to confirm, S to cancel, Enter for Start — pick a starter, and save a PyBoy save state right there. Every future training run loads that same state, so the agent's very first action is already standing in the world with a Pokémon in its party.

4Decide What the Agent Sees and Can Do

The agent's "eyes" are a small downsampled, grayscale copy of the current Game Boy screen — nothing else, no game-state summary. Its "hands" are seven buttons: the four directions, A, B, and Start. One decision cycle looks like: see a frame, choose a button, hold it for a short burst of emulated frames, look again. That's the entire loop, repeated thousands of times per run.

5Design the Reward Function

This is the actual hard part. Pokémon never displays a score, so "doing well" has to be defined by hand — and it has to be read out of the game's memory, since nothing about it appears on screen as a number. That's possible because a fan project called pret/pokered has fully reverse-engineered what every byte of the game's memory means, so it's possible to know, every single frame, exactly how many badges the player has, how much HP either side of a battle has left, and whether a battle is even happening.

Here's the reward function as it currently stands:

SignalReward
Visiting a new tile+0.5
Earning a gym badge+10.0
Leveling up the party+1.0 / level
Taking damage−0.5 × HP lost
Catching a new species (first time)+5.0
Catching any wild Pokémon+0.3 × its level
Damaging the opponent (every turn)+0.3 × HP taken
Winning a wild battle+0.5
Winning a trainer battle+2.0
Losing a battle−1.0
Running from a wild battle−0.5
A real snag worth knowing about: the game's own "are we in a battle" flag changes the exact same way whether a wild Pokémon fainted or the player just pressed Run — so telling a real win apart from a flee means also checking whether the opponent still has HP left the instant the battle ends. And the very first battle in the game — a mandatory, unfleeable fight against your rival, right after picking a starter — turned out to be a real early wall: without a reward for damage dealt turn-by-turn, the agent could get stuck cycling through the battle menu indefinitely, since the only reward it could reason about was a full win, and it never landed one. A stuck agent is usually a sign the reward function has a gap, not that the model is broken.
6Train It

Training means running several emulator instances in parallel, invisibly (no window, since drawing to a screen is one of the slower parts of emulation and nobody's watching them), while a neural network absorbs a stream of frames, actions, and rewards and gradually adjusts itself toward whatever tends to produce higher reward. Progress gets checkpointed to disk periodically, so it can survive a restart or be resumed later without losing anything.

python train.py --rom your_rom.gb --init-state init.state \
    --num-envs 7 --timesteps 1000000

There's no shortcut on time here — this is inherently slow, since every step is one emulator frame at a time. Hours, realistically, before there's much worth watching.

7Watch a Checkpoint Play
python play.py --rom your_rom.gb --init-state init.state \
    --model sessions/run/ppo_red_100000_steps.zip --speed 3

The --speed flag runs the emulator faster than real-time for a visible window (uncapped at 0) — useful once you're past the "is this even doing anything" stage and want to fast-forward to see how far a checkpoint has actually gotten.

8Or — Skip the Manual Coding Entirely

Everything in steps 2 through 7 can be done by describing what you want to an AI coding assistant instead of writing it by hand. This project actually was built that way — through a running conversation, not by hand-authoring every file up front. That includes not just the initial setup, but the ongoing back-and-forth of watching it play, noticing something's wrong, and fixing it.

Some real examples of what that conversation looked like in practice:

Set up a Python project that trains an AI to play Pokémon Red using PyBoy, Gymnasium, and Stable-Baselines3. I have a ROM at roms/PokemonRed.gb. Walk me through creating a starting save state too.
Add rewards for winning battles and catching Pokémon, using real RAM addresses — look up the pret/pokered disassembly for the exact memory locations.
The agent seems stuck at the first battle and never progresses past it. Can you check the reward function for gaps?
Can we tell a real win apart from the agent just running away? Also add a penalty for fleeing.
Let's watch the current checkpoint play in a window, and speed it up so it's not real-time.

None of that requires knowing Python going in, or understanding PPO's math, or already knowing which memory address holds a Pokémon's HP — that's exactly the kind of thing worth asking about instead of looking up. The useful skill isn't writing the code yourself, it's noticing when something looks wrong (stuck behavior, a reward that doesn't match what you intended) and being able to describe it clearly enough to get it fixed.

Progress Updates
Posted as the project moves — newest first.
September 2026

Past 3.6 million training steps. The agent reliably beats the mandatory rival battle now — that early wall came down once a per-turn "damage dealt" reward was added, giving it feedback throughout a fight instead of only at the very end. Current behavior of note: it's found Viridian Forest and taken up grinding levels there, since easy repeatable wild-battle wins against low-level Bug Pokémon are currently the highest-reliability reward available to it. Also added: a bonus for catching wild Pokémon that scales with their level, and bumped the "visit a new tile" reward up substantially to push back against how attractive forest-grinding has become. Next real milestone to watch for: the first gym badge, in Pewter City, just past the forest.
